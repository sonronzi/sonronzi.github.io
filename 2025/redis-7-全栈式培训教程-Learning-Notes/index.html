Redis介绍

Redis 功能特性

  • Redis 英文全称是 Remote Dictionary Server（远程字典服务）
  • Redis 是完全开源的，使用 ANSI C 语言编写，遵守 BSD 协议，是一个高性能的 Key-Value 数据库
  • Redis 提供了丰富的数据结构，例如 String、 Hash、 List、Set、SortedSet 等等
  • Redis 的数据是存在内存中的，但 Redis 也可以通过定期策略或者手动操作进行持久化数据
  • Redis 广泛应用于缓存、分布式锁等多种场景；同时 Redis 支持事务、持久化、LUA 脚本、发布/订阅、缓存淘汰、流技术等多种功能特性
  • Redis 提供了主从模式、Redis Sentinel 和 Redis Cluster 集群架构方案


Redis 适用场景

  • 热点加速/缓存加速
    • 缓存作为 Redis 最主要的功能，没有有之一，尤其是作为互联网应用上的热点场景，使用非常多,比如像高并发下的数据加载
  • 分布式会话/共享会话
    • 一个分布式 Web 服务将用户的 Session 信息保存在各自服务器，如果节点故障或者是用户刷新一次可能就需要重新登录，这样显然有问题。实际上，我们通常使用 Redis 将用户的 Session 进行集中管理，每次用户更新或者查询登录信息都直接从 Redis 中集中获取
  • 排行榜场景
    • 在互联网应用中，有各种各样的排行榜，如电商网站的月度销量排行榜、社交 APP 的礼物排行榜、小程序的投票排行榜等等。Redis 提供的zset 数据类型能够快速实现这些复杂的排行榜
  • 分布式计数器/集群计数器
    • 我们知道，单机下面我们可以利用原子操作/类型实现计数器，那么如果是布式环境呢？比如电商网站商品的浏览量、视频网站视频的播放数等。为了保证数据实时效，每次浏览都得给+1，并发量高时如果每次都请求数据库操作无疑是种挑战和压力。Redis 提供的 incr 命令来实现计数器功能，内存操作，性能非常好，非常适用于这些计数场景
  • 最新消息
    • Redis 列表结构，LPUSH 可以在列表头部插入一个内容 ID 作为关键字，LTRIM 可用来限制列表的数量，这样列表永远为 N 个 ID，无需查询最新的列表，直接根据 ID 去到对应的内容页即可
  • 请求限流
    • 主要用于集群限流
  • 分布式锁实现
    • 很多公司中都使用了分布式技术，分布式技术带来的技术挑战是对同一个资源的并发访问，如全局 ID、减库存、秒杀等场景，并发量不大的场景可以使用数据库的悲观锁来实现，但在高并发场景中，利用数据库锁来控制资源的并发访问性能极低，我们可以利用 Redis 的 setnx 功能来编写分布式的锁


Redis 周边对比

同类产品对比(memcached)

  • Redis 支持数据的持久化，可以将内存中的数据保存在磁盘中，重启的时候可以再次加载进行使用
  • Redis 不仅仅支持简单的 key-value 类型的数据，同时还提供 list，set，storted set，hash 等数据结构，同时支持发布/订阅、消息等多种特性
  • Redis 支持数据同步与备份，比如 master-slave 模式的数据同步与备份

与传统数据库关系(mysql)

  • Redis 是 key-value 数据库(NoSQL 一种)，mysql 是关系数据库
  • Redis 数据操作主要在内存，而 mysql 主要存储在磁盘
  • Redis 在某一些场景使用中要明显优于 mysql，比如计数器、排行榜等方面
  • Redis 通常用于一些特定场景，需要与 Mysql 一起配合使用
  • 两者并不是相互替换和竞争关系，而是共用和配合使用



Redis 环境安装

安装前置条件

操作系统说明

  • Redis 是用 ANSI C 编写的，可以在大多数 POSIX 系统上运行，比如 Linux、*BSD 和 Mac OS X，没有外部依赖
  • Linux 和 OS X 是 Redis 开发和测试最多的两个操作系统
  • 官方推荐使用 Linux 部署，Windows 版本没有官方支持

操作系统参数设置

  • /etc/sysctl.conf 中设置 vm.overcommit_memory = 1，并用 sysctl vm.overcommit_memory=1 立即生效
    • 0：内核将检查是否有足够的内存分配给程序，如果没有则申请失败，并把错误返回给应用进程。而在 Redis 中这个错误就会表现为“Cannot allocate memory”，然后触发 OOM
    • 1：表示内核允许超量使用内存直到用完为止
    • 2：表示内核决不超量使用内存，即系统整个内存空间不能超过 swap+50%的 RAM 值，50%是 overcommit_ratio 默认值，此参数支持修改
  • 配置大内存页面，echo never > /sys/kernel/mm/transparent_hugepage/enabled（只是临时生效），并同过下面命令进行永久生效
  • 关闭交换 swap 内存，swapoff -a，并通过 vim /etc/fstab 将交换内存注释掉(确保物理机有够用的物理内存


源码安装单机版

  • 安装目录规划
    • 根目录：redis
    • 子目录：
      • bin 程序目录
      • conf 配置文件
      • data 数据目录
      • run 进程目录
      • log 日志目录
